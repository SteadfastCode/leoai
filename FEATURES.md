# FEATURES.md — leo-nightly workqueue

**This file is the ONLY source of work.** Never read `docs/wishlist.md`, `CLAUDE.md`, or any
other doc as a source of items. `docs/wishlist.md` still contains full specs for features that
already shipped — treating it as a queue re-implements live code.

**Checkboxes here are for Daniel to read. They are NOT machine state.** Item selection reads
`ops/leo-nightly/state.json` on `origin/main` and nothing else. The routine updates both in the
same commit; if they ever disagree, `state.json` wins.

> **Resolved 2026-08-10:** build-state.js now parses ticked lines and carries forward items it
> has already worked but that FEATURES.md no longer lists. Ticking a box and moving a finished
> line into Completed Items are both safe — neither drops the item from state.json, so the
> `dependsOn` lookups LEO-005, LEO-023, LEO-025 and LEO-030 make against completed items keep
> resolving. Deleting an item that was never started still retires it.

**Selection rule:** the item with the lowest `order` in `state.json` whose status is `pending`,
whose `dependsOn` are all `done`, and whose `attempts < 2`. `order` is this file's position,
regenerated by `build-state.js` — **so priority IS list position, and the `LEO-nnn` id is
permanent identity, never renumbered.** Ledger history joins on the id; renumbering one would
silently rewrite what past events refer to. To reprioritize, move the whole item block and rerun
`node ops/leo-nightly/build-state.js` (the routine also regenerates at claim time, so a
forgotten regen self-heals).

**When the queue is drained, stop silently.** A quiet night is normal. Do not notify, do not
look for other work, do not invent items.
