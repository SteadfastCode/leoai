`dashboard/` was modified.

**Needs Daniel, by hand:** (1) top up Anthropic credits at console.anthropic.com — this is the
only thing standing between the routine and normal throughput; (2) place a superadmin `X-API-Key`

**Worth a decision, not just a fix:** the default-deny baseline rule has now produced **20
consecutive days of zero throughput** for an external billing condition that no run can clear. The
rule is correct in itself — merging into this baseline would auto-revert healthy code on the
post-deploy smoke. But "block every item until a human tops up credits" may not be the intended
failure mode for a month-long outage. A narrower rule is available now that push is known to work:
when the *only* failing baseline check is the Claude-dependent one, the routine could still ship
items that touch no Claude path, deferring the deploy rather than the whole run. That is a policy
change for Daniel to make, not for a run to assume.
